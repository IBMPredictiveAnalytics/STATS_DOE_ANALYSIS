STATS DOE ANALYSIS Extension Command

Design of Experiments: generate optimal, factorial, screening, response-surface, and other experimental designs; analyze the resulting (or an existing) dataset; and plan sample size with a power calculator. This page is organized to match the dialog: each section below corresponds to one of the dialog's buttons (Factor Settings, Options, Constraints, Design Options, Analysis, Output, Screening, Power). The Help (?) button on the main dialog opens this page; the buttons on each individual sub-dialog do not open their own help (a limitation of the dialog platform), so use the links below to jump straight to the section you need.

  • Main Dialog — Generate Design, Variable Names, Model Type, Design Type, Output Dataset
  • Factor Settings — Lows, Highs, Centers, Round-tos, Levels, Factors, Mixtures
  • Options — Optimal Design search algorithm settings
  • Constraints — restrict the candidate design region
  • Design Options — randomize, blocks, replicates
  • Analysis — fit a model, plots, optimization, variable selection
  • Output — confounding, tables, HTML export
  • Screening — screening center points, Augment to CCD
  • Power — power and sample size planner

How the dialog is organized (3.1.0)

The main dialog follows the order of a study. Most runs only analyze data that already has results; creating a design is optional.

Variables (left and middle). Drag from the variable list: Factors (the columns holding the factor settings; FACTORVARS), Responses (RESPONSEVAR) and, optionally, numeric factors to Treat as categorical (CATEGORICAL). Analyze the responses is ticked by default. If no factors are dragged, the factors saved with a design generated by this procedure are used, or detected from the data.

New design (buttons, right, top). Tick Create a new design and open Create Design: choose the design type and model, then fill in the Factor table — one row per factor with Name, Low, High, Levels and Categorical (up to 15 rows; keywords NAMEn LOWn HIGHn LEVELSn FACTORn) — and name the Output Dataset. Number of factors (NFACTORS) fixes how many factors there are: blank names become A, B, C … and blank Low/High become −1 and +1, so only the rows you want to change need typing; with more than 15 factors the extra ones are added the same way. Read the factor table from the active dataset (FACTORSFROMDATA=YES) takes any number of factors from a dataset with one row per factor and columns Name, Low, High and optionally Levels and Categorical (type or paste it, e.g. from Excel, into the Data Editor first). For more than 15 factors, or for centers, rounding and mixtures, type the factor names in Or factor names and give the settings as lists in Factor Lists (LOWS, HIGHS, CENTERS, ROUNDTOS, LEVELS, FACTORS, MIXTURES); use the table or the lists, not both. A categorical row without Low/High is coded 1 to Levels. In Factorial and Taguchi designs every row is a design factor. Design Options, Options, Constraints, Screening and Power follow.

Analyze buttons (right, below). Analysis (charts; optimize on/off and goals), Model (standard model or exact terms, selection, Box-Cox, predictions), Optimizer (limits, weights, importance, held factors), Mixture/Taguchi, Output. Standard model (TERMSET=TS_LINEAR, TS_2WAY, TS_3WAY, TS_LINSQ, TS_QUAD, TS_FULL) picks a whole model; Model terms (TERMS) lists exact terms and takes precedence. Adding and removing single terms with lists and arrows is done in the interactive Lab of the HTML report, which recalculates at once and writes the TERMS syntax to paste back.

A typical study: create the design → run the experiments and type the responses into the new dataset → analyze it → refine the model and settings in the interactive Lab → paste the Lab's syntax to keep the final result.

Interactive Model & Optimizer Lab (/OUTPUT LAB=YES, the default; needs EXPORTHTML=YES, also the default). The HTML report opens with a Lab built from the analyzed data:

  • 1 Refine the model: drag terms between Available terms and Terms in the model, double-click a term, or select terms and use the arrow buttons. Keep model hierarchical adds the lower-order terms an interaction needs and removes the interactions of a removed term. Reduce model removes the least significant term while its p-value is above the threshold (hierarchical backward elimination, as SELECTION=BACKWARD). The ANOVA (adjusted sums of squares, lack of fit), coded coefficients with effects and VIF, model summary (S, R-sq, adjusted and predicted R-sq), the equation in natural units, the Pareto chart and the residual plots are recalculated at once.
  • 2 Optimize responses: set the goal, limits, weight and importance of each response; move the factors with the sliders or by clicking a point on the response profiles. Fitted values, confidence and prediction intervals, each desirability d and the composite desirability D update immediately. Find the best settings searches the factor region (held factors stay fixed).
  • 3 Reproduce in SPSS: syntax that refits the final models (TERMS per response, SELECTION=NONE) and runs the optimizer with the settings chosen in the Lab, so the result is part of the SPSS output.

The Lab uses the same formulas as the procedure. When the page opens it recomputes every SPSS model (coefficients, sums of squares, p-values and the optimum's desirability); a warning appears at the top of the Lab only if anything differs. Box-Cox models keep the lambda chosen by SPSS. Mixture, Taguchi and split-plot analyses have no Lab. Nothing in the page is sent anywhere.

Further analyses and designs (3.1.0)

Next steps (/OUTPUT ADVISOR=YES, the default). After the analysis a Next Steps table states what the results imply for the next experiment, each with syntax that can be pasted and run: significant curvature or lack of fit (augment to a central composite design), factors with no significant effect on any response (refit without them; fix them in the next experiment), the best settings on the edge of the studied region (a new experiment shifted half a range in that direction), the path of steepest ascent or descent for a first-order model, too few error degrees of freedom (replicate), non-normal residuals (Box-Cox), over-fitting (backward elimination), and confirmation runs at the optimum. Syntax that refits a model reproduces it exactly (same coding and terms).

Profit or cost goal (/OPTIMIZE PROFIT='formula' PROFITGOAL=MAXIMIZE|MINIMIZE PROFITLIMITS="Response>=value ..."). Optimizes a formula of the predicted responses (original units) and the factor settings (natural units), for example PROFIT='120*Yield - 3*Cost - 0.02*Temp'. Allowed: response and factor names, numbers, + - * / ^ ( ), exp, log, log10, sqrt, abs, min, max, ifelse and comparisons (categorical factors as text, e.g. ifelse(Mat=="B", 5, 0)); nothing else can be called. Requirements are met exactly or the closest settings are shown and flagged. HOLD and SOLUTIONS apply. The output gives the best settings, the predicted responses, the profit and its 5th to 95th percentile range for a single run.

Uncertainty map (/OUTPUT UNCERTAINTYMAP=YES UNCERTAINTYLIMIT=value). Charts the half-width of the prediction interval for a single new run over pairs of numeric factors and reports the share of the region above the limit. The default limit is the largest half-width at any run of the experiment: beyond it the model is less certain than anywhere it was tested.

Analyze variability (/FITMODEL VARIABILITY=YES). For settings run two or more times, models ln(StdDev) on the factors (bias-corrected log variances, weighted by their known variances) and reports coefficients, ratios of standard deviations (high versus low setting), chi-square tests, observed and fitted standard deviations, and the fitted standard deviation at the optimizer's best settings.

Categorical factors in central composite and Box-Behnken designs. Factors marked categorical are no longer converted to numbers: the response-surface design in the numeric factors is run once for each combination of the categorical levels, and the design records which factors are categorical so the analysis treats them so.

Extreme-vertices mixture designs (DESIGNTYPE=EXTREMEVERTICES, EVDEGREE=0|1|2). For components with lower and upper bounds (LOWS, HIGHS; sum MIXTURESUM): the vertices of the constrained region, the centroids of its edges (EVDEGREE=1, default) or also of its 2-dimensional faces (2), and the overall centroid; AUGMENTMIX=YES adds check blends halfway between the centroid and each vertex. Bounds that cannot be reached are tightened and reported. The analysis uses the mixture models on L-pseudo-components.

Split-plot designs (HTC=hard-to-change factors, Factorial or Full factorial; /FITMODEL WHOLEPLOT=variable). Each setup of the hard-to-change factors in each replicate is a whole plot; with RANDOMIZE the whole plots, and the runs inside each, are run in random order, and a WholePlot column numbers them. When the data has a WholePlot column (or WHOLEPLOT names one) the analysis estimates the whole-plot and subplot variances by REML and tests whole-plot terms against whole-plot error and the other terms against subplot error. Use two or more replicates so that whole-plot error can be estimated.

Main Dialog — Generate Design, Model Type, Design Type

Generate Design (GENERATEDESIGN) turns design generation on or off. When checked (YES, the default), the procedure builds a new experimental design from Variable Names and Factor Settings, and the Output Dataset field becomes required. When unchecked (NO), the procedure instead reads the active dataset for analysis only — Variable Names, Factor Settings, Model Type, Design Type, and the Options/Constraints/Design Options screens are all unused in that mode and are greyed out, and Output Dataset becomes optional (it is only needed if you also use Augment to CCD on the Screening screen, which saves its own augmented dataset).

Variable Names (VARNAMES) lists one or more variable names for the design variables, separated by spaces. The order here sets the order used by every Factor Settings field.

Model Type (MODEL / FORMULA) selects the curvature model used when Design Type is Optimal Design: Linear, Quadratic, Cubic, CubicS (a version of the cubic model that stays non-singular for mixture variables), or a Custom Formula. A custom formula is an R model formula starting with ~, using +, *, and : for linear, interaction, and nested terms (e.g. ~x1 + x2 + x1*x2); the variable names in the formula must match Variable Names. Either Model Type or a custom Formula must be given, not both. Model Type only applies to Optimal Design — every other Design Type builds its own intrinsic run structure and ignores this setting.

Design Type (DESIGNTYPE) chooses the kind of design to generate:

  • Optimal Design — Monte Carlo D- or A-optimal search (see Options)
  • Factorial Design — full or fractional 2-level factorial, 2^k runs
  • Plackett-Burman Design — screening design, runs round up to a multiple of 4
  • Response Surface Design — for optimization studies
  • Box-Behnken Design — 3-level design for quadratic models
  • Central Composite Design (CCD) — factorial core plus axial/star points
  • Taguchi Design — orthogonal array, runs round up to a power of 2
  • Latin Hypercube Sampling — space-filling design for simulation
  • Definitive Screening (DSD) — 3-level screening design, runs = 2k+1
  • Full Factorial — every combination of every factor's levels

Output Dataset (SAVE DATASET) names the dataset that receives the generated design (or the augmented design, if Augment to CCD is used). The name must not already be in use. It is required whenever Generate Design is checked; otherwise it is optional.

Factor Settings

One value is given per variable in Variable Names (or a single value to apply to all variables). The first four properties do not apply to factor variables, but a value must still be given for them if the design mixes factor and non-factor variables, to keep every list aligned by variable position.

  • Lows (LOWS) — minimum values
  • Highs (HIGHS) — maximum values
  • Centers (CENTERS) — centering values; left blank, the midpoint of Lows/Highs is used automatically
  • Round-tos (ROUNDTOS) — number of decimal places to round sampled values to (e.g. 2 rounds to two decimal places)
  • Levels (LEVELS) — number of distinct levels to sample from; 0 or blank uses a default (2 for most designs, or more automatically for a curvature Optimal model, to avoid a singular design)
  • Factors (FACTORS) — Yes/No: is this variable categorical?
  • Mixtures (MIXTURES) — Yes/No: is this variable part of a mixture? Mixture variables are always sampled between 0 and 1, and if any variable is a mixture the constant term is automatically suppressed. A variable flagged as both Factor and Mixture is treated as a mixture.

Lows and Highs are required for every ordinary (non-factor, non-mixture) variable.

Options

Controls the Optimal Design search algorithm.

  • Criterion (CRITERION) — D (a scaling of the generalized variance of the design matrix) or A (proportional to the average variance of the parameter estimates)
  • Center points (CENTER) — whether non-factor variables are centered before a design is evaluated
  • Random start (INITIAL) — Random or Nullification. Nullification successively adds points from fresh samples of candidate points and generally produces better designs, at the cost of more time
  • Design algorithm (DESIGNALG) — Exact (an exact design is calculated) or Approximate (an approximate theory design is calculated)
  • Repeats (REPEATS) — how many times the whole search is repeated, keeping the best design found (default 5)
  • Num. candidates (NUMCAND) — number of candidate points to generate; defaults to ten times the number of terms in the model
  • Trials (TRIALS) — number of runs in the design; defaults to the number of model terms plus five, must be more than the number of terms and no more than Num. candidates
  • Constant (CONSTANT) — include a constant term (automatically suppressed for mixtures)
  • Mixture sum (MIXTURESUM) — the sum mixture variables must add to (default 1)

Constraints

By default every point within the Lows/Highs ranges is a valid candidate. A constraint function (CONSTRAINTFUNC) restricts the candidate region across variables: it names a file containing an R function called dfilter that takes a candidate point's coordinates and returns TRUE (keep) or FALSE (reject). Example:


dfilter = function(x) {
    if (sum(x) <= .75) {
        return(TRUE)
    } else {
        return(FALSE)
    }
}

This keeps only candidate points whose coordinates sum to .75 or less. Only used with Optimal Design.

Design Options

  • Randomize run order (RANDOMIZE) — randomize the run order of the generated design
  • Blocks (BLOCKS) — number of blocks to divide the design into. Factorial designs are blocked directly; for all other design types each block is made of whole replicates, so REPLICATES must be a multiple of BLOCKS (otherwise BLOCKS is ignored with a warning). With RANDOMIZE, runs are randomized within each block.
  • Replicates (REPLICATES) — number of times to replicate the entire design (all design types). The Reps column numbers the replicates 1 to N.

Analysis

Analyze (ANALYZE) fits a model to the response and enables the rest of this screen.

Response Variable (RESPONSEVAR) names one or more response variables to analyze; with more than one, results are produced for each.

Create plots (CREATEPLOTS) turns on the plot options below it: Main Effects, Interactions, Cube Plot, Contour Plot, Residual Plots, Pareto Plot, Curvature Plot (average response at factorial/cube points vs. center points), and External Plots.

Optimize response (OPTIMIZERESPONSE) searches for factor settings that best satisfy an Optimization goal (OPTIMIZATIONGOAL): Maximize, Minimize, or Target. With multiple response variables, per-response goals can be given in Optimization goals (OPTIMIZATIONGOALS); any left unset fall back to the single Optimization goal.

Variable selection (VARSELECT) reduces the model with either the Method (VARSELMETHOD) Stepwise (AIC-based, direction set by Step direction / STEPDIR: Both, Forward, or Backward) or Best Subsets. Selection Trace, Fit Profile, Parsimony Plot, and Factor Map are optional diagnostic charts for the selection process.

Output

Confounding (CONFOUNDING) displays a table of the regression coefficients of each variable on all the others (this same checkbox also appears on the Options screen; both control the same setting). Additional tables: Effects table (EFFECTSTABLE), Residual tests (RESIDUALTESTS), VIF table (VIFTABLE, variance inflation factors), Optimal design detail table (OPTDETAILTABLE), and Screening summary (SCREENINGSUMMARY, an effect-ranking table for screening designs). Export HTML (EXPORTHTML) additionally writes an interactive HTML report; its location is set by HTMLPATH, or otherwise defaults to a timestamped file next to the dataset.

Screening

Screening center points (SCREENINGCENTERPTS) adds center points to a 2-level screening design; count (SCREENINGCENTERPTSCOUNT) sets how many. Only meaningful when Generate Design is checked.

Augment to CCD (AUGMENTTOCCD) is a sequential-design feature: it reads an existing factorial design and response data from the active dataset and adds axial (star) points to form a face-centered Central Composite Design, saved to a new dataset named in Output Dataset. Augment center points (AUGMENTCENTERPTS) sets how many center points to add. Unlike the other controls on this screen, Augment to CCD works whether Generate Design is checked or unchecked — the typical use is with Generate Design unchecked, augmenting a design you already ran.

Model (coded-factor analysis)

When Analyze is selected, responses are analyzed with the coded-factor model by default (/FITMODEL ANALYSISMODEL=CODED). Numeric factors are coded −1 (low) and +1 (high); a two-level text factor is coded −1 for its first level (set it with LOWLEVELS). Center points are recognized from a CenterPt/PtType column (0 = center, 1 = cube, −1 = axial) or, if there is none, from runs where every numeric factor is at its midpoint. VARNAMES must list the design factors, also when analyzing an existing dataset.

Default model: two-level designs — main effects, two-factor interactions and a center-point (curvature) term; response-surface designs (CCD, Box-Behnken or 3+ levels) — full quadratic; definitive screening — main effects and squares. Terms that are aliased with terms already in the model are removed, and the alias table shows what they are confounded with.

TERMS sets the model explicitly. Use factor names or letter codes (A, B, C … in VARNAMES order, I is skipped), joined with *, e.g. TERMS="A B C D A*B CTPT". Keywords: LINEAR, 2WAY, 3WAY, SQUARES, QUADRATIC, FULL, CTPT. A different model for each response: TERMS="Density: A B C D A*B CTPT; Odor: A B D A*B CTPT".

BACKWARD=YES removes the least significant term one at a time while its p-value is above ALPHAREMOVE (default 0.10), never removing a term that is part of a remaining interaction. ALPHA (default 0.05) sets the Pareto reference line; CONFLEVEL (default 95) sets interval widths.

Output for each response: factor coding, coded coefficients (effect, coefficient, SE, t, significance, VIF), model summary (S, R-squared, adjusted and predicted R-squared, PRESS), ANOVA with adjusted sums of squares, curvature, and lack-of-fit/pure error when replicated runs exist, the equation in natural units (one column per text-factor level), the alias structure for fractional designs, and unusual observations. Charts (from the Analysis dialog): Pareto and normal plot of standardized effects (Lenth’s method when there are no error degrees of freedom), main-effects and interaction plots of fitted means with the fitted center point, cube plot, contour plots and residual plots. ANALYSISMODEL=LEGACY restores the previous raw-unit behavior.

Factors for analysis-only runs

With GENERATEDESIGN=NO, VARNAMES may be left out. The extension then uses, in order: (1) the design information saved in the dataset — every design it generates stores its factor list as the data file attribute DOE_Factors (kept when the dataset is saved as .sav; view it with DISPLAY ATTRIBUTES); (2) otherwise, columns detected as factors: 2 to 7 distinct settings (and at most half as many as there are runs), excluding run-order, block, center-point and response columns. A Factors Used table shows which columns were used and why. When you do name the factors in an analysis, that list is saved in the active dataset’s attributes so the next analysis can omit VARNAMES (save the dataset to keep it).

More analysis options (Model… and Mixture/Taguchi… buttons)

  • Term selection (SELECTION=NONE|BACKWARD|FORWARD|STEPWISE, ALPHAENTER, ALPHAREMOVE): chooses terms by p-value and keeps the model hierarchical. BACKWARD=YES still works.
  • Box-Cox (BOXCOX=NONE|AUTO|LOG|SQRT|INVERSE|CUSTOM, LAMBDA): models Yλ; AUTO uses the best λ rounded to 0.5 and shows its confidence interval. The optimizer converts back to original units.
  • General full factorial: with DESIGNTYPE=FULLFACTORIAL, or factors listed in CATEGORICAL=, numeric factors with more than two levels are treated as categories. GROUPING=YES adds Tukey pairwise comparisons with letter groupings.
  • Response surface: CANONICAL=YES reports the stationary point and whether it is a maximum, minimum or saddle; SURFACEPLOT=YES draws 3-D surfaces.
  • Mixtures: components are those flagged MIXTURES=YES, all factors of a simplex design, or factors that add to the same total in every run. MIXMODEL=LINEAR|QUADRATIC|SPECIALCUBIC|FULLCUBIC, MIXCOMPS=AUTO|PSEUDO|PROPORTIONS, TRACEPLOT=YES; contour plots are ternary; the optimizer searches blends within the component ranges. New designs: DESIGNTYPE=SIMPLEXLATTICE (with LATTICEDEGREE) and SIMPLEXCENTROID, optionally AUGMENTMIX=YES (axial blends + centroid).
  • Taguchi: DESIGNTYPE=TAGUCHI or SNTYPE=LARGER|SMALLER|NOMINAL|NOMINAL2, with the replicate response columns in RESPONSEVAR: S/N, means and standard-deviation response tables (delta and rank), S/N ANOVA, main-effects plots and the predicted result at the best levels.
  • Plain-language summary (INTERPRET=YES, default): a Summary of Results table above each response's tables that states in words whether the model is significant, how much variation it explains and how well it should predict, which terms matter (strongest first), the size and direction of the largest effects, curvature, lack of fit, residual problems and cautions. Mixture, Taguchi and optimizer output get their own summaries. INTERPRET=NO turns it off.
  • Residual checks (shown with DIAGTABLE=YES): Anderson–Darling normality test of the residuals, Durbin–Watson statistic in run order (a drift or time trend shows as a value well below 2) and the largest Cook’s distance (above 1 = one run strongly changes the fit).
  • Prediction (PREDICT="Factor=value ...; Factor=value ..."): fitted value, its standard error, the confidence interval for the mean and the prediction interval for a single new run at each setting (separate settings with a semicolon; factor names or letter codes; factors left out are at their center or first level). Settings outside the tested range are flagged as extrapolation. Intervals use CONFLEVEL.
  • Optimizer extras (/OPTIMIZE): OVERLAY=YES overlaid contour plot of the region meeting every limit; CONFIRMRUNS=n interval for the average of n confirmation runs; ROBUST=YES ROBUSTSD=5 simulates setting errors and run-to-run variation around the optimum.

Optimizer

With Optimize Response, one goal per response (OPTIMIZATIONGOALS: MAXIMIZE, MINIMIZE or TARGET) and optional targets (OPTIMIZATIONTARGETS) are combined by the Derringer–Suich desirability method. On /OPTIMIZE: LOWERS and UPPERS give the acceptable limits (one value per response; a value is ignored where the goal does not use it), WEIGHTS and IMPORTANCE (0.1–10, default 1), HOLD="Factor=value ..." fixes factors, and SOLUTIONS lists the best distinct settings. Blank limits default to the observed range of the response. If any model contains the center-point term, only the cube corners and the center point are searched, because that model is not defined elsewhere.

STATS DOE ANALYSIS GENERATEDESIGN=NO VARNAMES=Bentonite BentRatio H2ORatio CoaterHz
  RESPONSEVAR=Density Odor ANALYZE=YES OPTIMIZERESPONSE=YES OPTIMIZATIONGOALS=TARGET MINIMIZE
  OPTIMIZATIONTARGETS=26.5 23.3
 /FITMODEL TERMS="Density: A B C D A*B CTPT; Odor: A B D A*B CTPT" ALPHA=0.10
 /OPTIMIZE LOWERS=20 0 UPPERS=30 32.7 HOLD="Bentonite=AC"
 /OUTPUT PARETOPLOT=YES MAINEFFECTS=YES INTERACTIONS=YES.

Power

A standalone power and sample size planner, independent of Generate Design — useful for deciding how many runs a design needs before building it.

  • Display power and sample size table (POWERTABLE) turns the calculator on
  • Effect sizes (POWEREFFECTSIZES, in standard deviation units) and Number of runs to evaluate (POWERRUNS) each accept one or more values, evaluated in combination
  • Significance level / alpha (POWERALPHA) — default 0.05
  • Target power (POWERTARGET) — default 0.8

An Operational Note

If there is only one design variable, it will always be named X1, and some numbers in the design evaluation table will be missing.
